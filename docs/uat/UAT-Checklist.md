\## วิธีบันทึกและรายงานผล



\### 1. ไฟล์นี้คือ "แบบฟอร์มต้นฉบับ" — อย่ากรอกทับ



ทุกครั้งที่เริ่มทดสอบรอบใหม่ ให้คัดลอกเป็นไฟล์ผลของรอบนั้น แล้วกรอกในสำเนา



```powershell

Copy-Item docs\\UAT-Checklist.md "docs\\uat\\UAT-Result-$(Get-Date -Format yyyy-MM-dd)-รอบ1.md"

```



เหตุผล: จะได้เทียบรอบต่อรอบได้ว่าข้อที่เคยไม่ผ่าน รอบนี้ผ่านหรือยัง และต้นฉบับยังสะอาดไว้ใช้รอบหน้า



\### 2. กรอกช่อง "ผล" ด้วยสัญลักษณ์เดียวกันทั้งไฟล์



| สัญลักษณ์ | ความหมาย | ต้องทำอะไรต่อ |

|:--:|---|---|

| ✅ | ผ่านตามผลที่คาดหวัง | ไม่ต้องทำอะไร |

| ❌ | ไม่ผ่าน | \*\*บังคับ\*\* ลงบันทึกในตาราง "รายการที่ไม่ผ่าน" ท้ายไฟล์ พร้อมใส่เลข `UAT-xx` ต่อท้าย ❌ |

| ⚠️ | ผ่านแต่มีข้อสังเกต (เช่น ข้อความกำกวม, ช้าผิดปกติ) | ลงบันทึกเหมือนกัน แต่ตั้งความรุนแรงเป็น "ต่ำ" |

| ➖ | ทดสอบไม่ได้รอบนี้ (เช่น ยังไม่มีมือถือทดสอบ) | เขียนเหตุผลไว้ในช่องเดียวกัน และต้องกลับมาทำให้ครบก่อนปิด UAT |



ตัวอย่างการกรอก:



```

| 3.4 | กด "พักการส่ง" โดยไม่กรอกเหตุผล | ทำไม่ได้ — ต้องกรอกเหตุผลก่อน | ❌ UAT-03 |

| 4.5 | อัปโหลดรูปจากมือถือ | ไฟล์ที่ส่งจริงไม่เกิน 2 MB | ⚠️ UAT-04 (ช้า \~5 วิ) |

```



\### 3. ทุกข้อที่ ❌ / ⚠️ ต้องมีบรรทัดใน "รายการที่ไม่ผ่าน"



บันทึกให้ผู้พัฒนาทำซ้ำได้ — ระบุ \*\*ใคร (รหัสพนักงานที่ login), ทำอะไร, เห็นอะไร\*\* และแนบรูปหน้าจอถ้ามี

ข้อความ error ให้คัดลอกมาทั้งบรรทัด อย่าสรุปเอง



\### 4. ส่งผลกลับอย่างไร



แนบ \*\*ไฟล์ผลของรอบนั้น 1 ไฟล์\*\* + โฟลเดอร์รูปหน้าจอ (ถ้ามี) แล้วสรุปหัวข้อสั้น ๆ ว่า

"ผ่าน x/61 · ไม่ผ่าน y ข้อ (สูง a / กลาง b / ต่ำ c) · ยังทดสอบไม่ได้ z ข้อ"



\### 5. เกณฑ์ปิด UAT (ตกลงกันก่อนเริ่มทดสอบ)



| เงื่อนไข | เกณฑ์ |

|---|---|

| หมวด 7 (การแยกข้อมูลตามสาขา) | ต้องผ่าน \*\*ครบทุกข้อ\*\* — ข้อเดียวไม่ผ่าน = ปิด UAT ไม่ได้ |

| ข้อบกพร่องความรุนแรง \*\*สูง\*\* | ต้องเหลือ \*\*0 ข้อ\*\* |

| ข้อบกพร่องความรุนแรง \*\*กลาง\*\* | แก้ให้หมด หรือมีข้อตกลงเป็นลายลักษณ์อักษรว่าเลื่อนไปหลัง go-live |

| ข้อบกพร่องความรุนแรง \*\*ต่ำ\*\* | บันทึกไว้เป็นงานถัดไปได้ ไม่บล็อก |

| ข้อที่ยังทดสอบไม่ได้ (➖) | ต้องเหลือ 0 ข้อ |



\*\*นิยามความรุนแรง\*\*



\- \*\*สูง\*\* — ข้อมูลรั่วข้ามสาขา/ข้ามสิทธิ์ · ข้อมูลหายหรือผิด · ทำงานหลักไม่ได้เลย (แจ้งงาน/ยืนยัน/ปิดงาน)

\- \*\*กลาง\*\* — ทำงานได้แต่ผิดกฎที่ตกลงไว้ (เช่น BR-1 คำนวณวันผิด) หรือมีทางอ้อมให้ทำงานต่อได้

\- \*\*ต่ำ\*\* — ข้อความ/การจัดหน้า/ความสวยงาม ไม่กระทบข้อมูลและการทำงาน

\## ข้อจำกัดที่ทราบแล้ว (ยังไม่อยู่ในขอบเขต)



1\. \*\*SSO ยังเป็นของจำลอง (D3)\*\* — หน้า login ให้เลือก/พิมพ์รหัสพนักงานได้เอง \*\*ห้ามขึ้น production\*\*

&#x20;  จนกว่าจะเปลี่ยน `ISsoClient` เป็นตัวจริง (แก้ที่ `ServiceRegistry` บรรทัดเดียว)

2\. \*\*SMTP ยังไม่ได้ต่อของจริง (D5)\*\* — เมลถูกเขียนเป็นไฟล์ `.eml` · เปลี่ยนเป็นส่งจริงได้ที่ Web.config (D28)

3\. \*\*ยังไม่รองรับวันหยุดนักขัตฤกษ์ (D6)\*\* — BR-1 คิดแค่เสาร์-อาทิตย์

4\. \*\*เปลี่ยนตัว Messenger กลางคันไม่ได้ (D11)\*\* — ออกแบบไว้ให้สาขามี Messenger ประจำคนเดียว

5\. \*\*ยังไม่มีหน้าจัดการ master data / role\*\* — ต้องแก้ที่ตาราง `tblUserRole` ผ่าน SSMS

6\. \*\*รายงานยังไม่มี KPI เชิงเวลา\*\* (เวลาเฉลี่ยจนเสร็จ ฯลฯ) — อยู่ในหัวข้อ Enhancements §11

7\. \*\*HTTPS\*\* — ตอน dev เป็น HTTP ขึ้น production ต้องเปิด HTTPS แล้วตั้ง `requireSSL="true"`

&#x20;  ทั้งใน `<forms>` และ `<httpCookies>`
